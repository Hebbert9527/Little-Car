## 共享 I2C1 接线

| 信号 | STM32 | 你们确认的排针 | 连接 |
|---|---|---|---|
| SCL / D15 同行靠里针 | PB8 | CN10-3 | IMU SCL 和 OLED SCL 并接 |
| SDA / D14 同行靠里针 | PB9 | CN10-5 | IMU SDA 和 OLED SDA 并接 |
| GND | GND | 板上 GND | IMU、OLED 与 NUCLEO 共地 |

默认总线为 I2C1、100 kHz。采用与 STM32 兼容的 3.3 V 信号电平，按模块规格供电。上下排针只要连接同一 PB8/PB9 网络，就共用这条总线；没有另建软件 I2C。

老师截图和本目录的课件没有给出 OLED 控制器/分辨率/地址。当前默认按带内部电荷泵的 **SSD1306、128×64、7 位地址 0x3C** 编译；这是一项待实物确认的配置，不能据此认定屏幕型号。支持 128×32、0x3D 参数覆盖；SH1106 需要不同驱动。

## 运动标定

双轮版使用轮径 68 mm、中心距 175 mm。按轮上标记复核后的四倍频计数是左 1559.45、右 1561.60 计数/圈。当前默认使用两路有方向的硬件计数。需要重现旧右轮单路构建时追加 `--define W4_SINGLE_ENCODER`。

- 右轮 E1A 接 PA7/TIM3_CH2，E1B 接 PA6/TIM3_CH1。
- 左轮 E2A 接 PC6/TIM8_CH1，E2B 接 PC7/TIM8_CH2。

常规编译保留运动标定锁。现场联调版确认了左右前进计数为正及 IMU 逆时针角度为正，再使用实测方向和配置开启 GOTO。架空编码器验证、实物带载精度和场地路线分别记录在项目上级 README。

当前车尾前置版定义 `W4_REAR_FORWARD`，原物理右轮作为逻辑左轮、原物理左轮作为逻辑右轮，驱动和编码器的符号均随新前方调整。GOTO、STOP、RESET 指令沿用。用户确认右侧雷达图 +X 指向当前车头，左侧导航图初始前方由 RESET 设为 +Y。

## 开机与命令

先保持小车静止。IMU 自动读取身份、唤醒、配置量程/滤波/采样率，连续 200 次静止采样完成零偏标定。IMU 航向从相对零开始，位姿层仅加一次世界偏置，使初始朝向为正 Y。屏幕逐块初始化，128×64 通常需要数秒；任务从开机起每 50 ms 运行，运行时每次最多刷新一个 16 字节块；有变化时优先更新，无变化时循环重写现有块以持续展示 mutex 的真实共享访问，完整画面不是 20 FPS。

每条命令以换行结尾，可由 PC 界面发送：

```text
GOTO,0,1.4
GOTO,-0.7,0.7
GOTO,0.7,-0.7
STOP
RESET
```

双轮版的 `GOTO,0,d` 表示沿 RESET 时保存的朝向行驶 `d` 米，`d` 的范围为 0 至 2。车头误差超过 3° 时先原地对齐，等车轮停稳再开始累计行程。定长行驶中，两轮目标速度均值保持 0.40 m/s，默认用受限差速纠正横偏和航向，各轮仍用编码器 PI 跟踪目标。定义 `W4_DISABLE_STRAIGHT_CORRECTION` 可恢复相同的两轮目标。两轮编码器有符号行程的平均值到达 `d` 后立即输出零 PWM。地面停车距离还取决于惯性和轮胎滑移。

双轮版坐标路线从当前世界位姿开始，接受每个坐标在 −2 至 +2 米之间的 `GOTO,x,y`。若 X 与 Y 均需移动，先沿 Y 到目标 Y，再转到 X 轴方向。用 `RESET` 可将当前起点设为 `(0,0)`，当前车头定义为正 Y。停止且 IMU 已就绪时发 `RESET`，收到 `RESET_PENDING` 后等待下一个 10 ms 控制周期完成复位，再发送一条 GOTO。定长直行从当前位姿起算。运动期间 GOTO/RESET 会被拒绝，STOP 独立锁存，队列满也能请求停车。

例如，从原点发 `GOTO,1,1` 会先沿 +Y 行驶，接近目标 Y 线时停车，双轮停稳后原地右转 90°，朝目标 X 行驶。拐点停车按第一段沿程判断，横向偏移不会禁止转向。路径点间距默认 5 cm。雷达点云仅用于显示，试跑前需确认实物墙与转向空间。

## 实际 mutex 与调度证据

IMU 的身份探测、寄存器写入、采样和 OLED 分块写入（包括静止画面的周期重写）均通过 `w4_i2c_bus.c` 的同一个 `Mtx_I2C1`，使用 `osMutexPrioInherit`。异步 I2C 在完成、总线空闲或确认硬件复位后才归还调用方缓冲区并释放 mutex。IMU 超时会使样本无效，连续错误触发恢复和重新初始化。

PC 程序说明见 `README_PC.md`。默认每 50 ms 发送 IMU/导航数据，每秒发送诊断：

- `B`：IMU/OLED 各自获取锁次数、IMU 最大等待 tick、OLED 最大持锁 tick、完成次数、传输超时、恢复次数；tick=1 ms。两种 acquisition 都持续增加才证明两个设备都在访问。
- `S`：定时器触发、采样完成、采样失败、信号量合并、IMU 校准标志、OLED 状态（0 未配置、1 初始化、2 就绪、3 IO 错误）。以两个时间点的完成数差 / 时间差计算实际采样率。
- `T`：每秒轮换一个任务，带优先级、配置栈字节、唤醒次数、最大实际周期/耗时/抖动（微秒）、截止时间错失、最小空闲栈。事件任务的周期是唤醒间隔，不应与固定周期等同。
- `Q`：毫秒、LiDAR 队列当前深度/容量、命令队列深度/容量、路径队列深度/容量、命令队列满次数、路径回压次数。LiDAR 额外序号/覆盖检查见调试器 `LidarDma_GetStats()`。

IMU 10 ms 定时器→二值信号量；编码器/位姿/PID/电机合并在 10 ms 控制任务；OLED 50 ms；蓝牙周期发布 50 ms，DMA 发送事件驱动。耗时统计包围实际处理段，排除下一次事件等待；包含被高优先级任务抢占的墙钟时间，不是纯 CPU 占用。

## 上板验收清单

1. 同时连接真实 IMU/OLED；确认 OLED 状态2、B 帧两设备计数增长；缺失设备须能看到失败而不是伪造成功。
2. 分别记录 IMU 单独运行和 OLED 内容持续变化时至少 30 s 数据，比较实际采样率、最长间隔、等待/持锁时间和合并触发数。必要时用逻辑分析仪解码 PB8/PB9 的 MPU 地址及 OLED 地址，证明没有交错事务。
3. 展示各任务优先级、配置栈和实测余量、10/50 ms 周期与事件唤醒；展示三个队列的数据结构、容量8/8/64和溢出/回压策略。
4. 完成三条目标试验，每次仅发一条 GOTO。用实际测量记录终点 X/Y 误差和航向误差，同时保留 PC 遥测；不能只把内部里程计当成真实位置。
5. 运动中测试 STOP、传感器失效停车、复位后再次导航。验收前完成 PID 参数和几何标定；现场不调参。

主机 mock 测试和 ARM 编译仅证明软件回归与链接；OLED 型号、接线、电气时序、物理路径和终点精度均需实物验证。

## 迷宫固件（第 54 节）

在本目录执行 `python -B tools/build.py --maze`，生成 `build/maze/Week4_Integrated.hex`。该入口复用第 53 节的双编码器、车尾前置、实测标定和诊断配置。PC 指令见 README_PC.md。普通 Build 保留原有用途。

| 模块或逻辑轮 | 实车连接 |
|---|---|
| MPU6500 与 OLED | I2C1 PB8/PB9，CN10-3/5 |
| HC-04 RX/TX | STM32 USART3 TX/RX，PC10/PC11，CN7-1/2 |
| C1 RX/TX | STM32 USART1 TX/RX，PA9/PA10，CN10-21/33 |
| 逻辑左（原右） | PB6/PB7 TIM4 CH1/2，编码器 PA6/PA7 TIM3，1561.60 计数/圈 |
| 逻辑右（原左） | PB14/PB15 TIM12 CH1/2，编码器 PC6/PC7 TIM8，1559.45 计数/圈 |

迷宫前进以左右 30.99% / 35.59% 为 0.18 m/s 的基础前馈，编码器 PI、起步及转向补偿继续生效。网格间距 0.10 m，障碍中心按 0.20 m 半径膨胀。连续路段在 0.46 m 内，从实测自由格中选择，最高前进目标 0.18 m/s。

实车待核对的几何量包括 C1 到双轮轴心的前向与左向偏移（默认均为 0 m，可通过 --define W4_C1_FORWARD_OFFSET_M=... 和 W4_C1_LEFT_OFFSET_M=... 设置）、车身转动包络及刹停余量。原日记确认 C1 的零度朝车头。默认俯视顺时针角度增加，需用左右侧单个目标验证安装朝向，角号可通过 W4_C1_ANGLE_SIGN 设置。IMU 负责航向，点云匹配只修正地图与里程计之间的平移。
