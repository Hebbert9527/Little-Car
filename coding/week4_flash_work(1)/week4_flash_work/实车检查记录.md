# Week4 实车检查记录

日期：2026-11-18。用户确认车轮电机动力断开；本次没有给电机通电或让小车自主行驶。烧录固件中的运动标定锁保持启用。

| 项目 | 当前实测 |
| --- | --- |
| MCU / 固件 | ST-LINK 连接 STM32F446；读取片上 Flash 并逐字节对照本次编译的 HEX 中 83504 个有效字节，一致。CPU 运行，故障码为 0。 |
| 蓝牙 | 连接 `Group40-BLE`（`C4:25:01:17:00:02`），FFE1 同时支持通知、读取和写入。实际发送 `STOP`，收到 `A,1,STOPPED,STOP_LATCHED`，随后只读核对停止请求代数与控制任务已消费代数均为 1、停止锁存已清除；发送 `GOTO,0,1.4`，收到 `A,2,REJECTED,HARDWARE_NOT_READY`，符合运动锁状态。另发送 `RESET`，收到 `A,3,REJECTED,RESET_REQUIRES_STOP_AND_IMU`，符合未完成 IMU 标定的情况。 |
| 遥测 / 调度 | 雷达供电前被动接收约 30 秒，解出 665 帧，其中 N 553、B/S/Q/T 各 28，解析坏帧和序号缺口均为 0。最长 27 秒的 S 帧区间内，IMU 定时触发 2700 次、完成采样 2700 次，失败 0、信号量合并 0。雷达恢复后另有一次约 94 秒连续接收，得到 1920 条 P 帧和 1926 条 N 帧，序号均无缺口；另有重连时订阅超时或断开的情况，不能将一次连续接收当作长期稳定性验收。 |
| 共享 I²C / OLED | 同一 27 秒内，IMU 获取 I²C 锁 2700 次，OLED 获取 540 次，无传输超时或恢复；固件报告 OLED 状态 2（READY），用户确认屏幕亮起并显示文字。 |
| 队列 | 在板上读取三个 FreeRTOS 队列的容量和消息尺寸：`Q_Lidar` 8×16 B、`Q_Cmd` 8×16 B、`Q_Path` 64×16 B。雷达恢复后的一个 12.593 秒窗口，LiDAR HT/TC 各 126 次，Q_Lidar Put/Get 各 252 次、队列满 0、丢块 0；另一个 12.587 秒窗口 Put/Get 各 252 次、队列满 0，但驱动丢弃 4 个未能确认稳定的半区，过期/覆盖相关计数增长 4。计数不能单独区分真正覆盖与其他稳定性检查失败。GOTO 经命令通路被规划任务按运动锁拒绝；尚不能证明 Q_Path 的真实路点生产和消费。 |
| 右轮编码器 | 电机断电手动转动约一圈时计数从 31 到 524，增 493；之后标记后手转两整圈，计数从 524 到 1432，增 908，约 454 个上升沿/圈。两次结果与原有 330/圈默认值不一致，尚需重复测量并确认轮与编码器的机械关系；没有自动修改配置。第二次检查过捕获数仍为 0。 |
| 电位器 | 用户转动旋钮前后，ADC 原始值从约 10 增至 4095，采样计数在增长，ADC 错误计数为 0。 |
| 电机输出 | TIM4/TIM12 四个 PWM 比较寄存器读取均为 0。因电机动力断开，电机转向、速度、PID 和急停的实际动力表现尚未测试。 |
| IMU 标定 | 用户确认水平静止后，IMU 仍未完成 200 样本静止标定。例次原始数据解码约为 `gx=5.53°/s, gy=14.42°/s, gz=-1.03°/s`；当前固件要求三个原始陀螺轴的绝对值均不超过 5°/s，因此持续拒绝标定。尚不能仅凭该现象断定硬件故障或允许放宽安全条件。 |
| LiDAR | 最初 DMA 接收计数不变、HT/TC 为 0；用户发现雷达正极未连接，接通后进入 STREAM，真实点数据和 DMA/队列计数增长。一个 12.548 秒蓝牙窗口收到 251 条 P 帧，序号无缺口；P 帧序号连续不代表 DMA 半区完全没有丢失。用户放置、移开障碍物前后，雷达 120°–160° 扇区的点距离中位数从约 771 mm 增至约 2440 mm（分别 35、31 个样本），变化与用户操作一致；两个采集窗口有时间间隔，尚未排除环境中其他变化。 |
| 按键 | 用户分别按下两个外接按键，`key1_irq_count` 从 1 增至 5，`key2_irq_count` 从 2 增至 6，说明中断输入有响应。现有 RTOS 构建未执行旧裸机按键业务处理，故不能据此认定原有按键控制功能已工作。 |
